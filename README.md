# nosql-mongodb-project

Учебное веб-приложение (интернет-магазин) на Node.js и Express, созданное в рамках изучения серверной разработки и работы с базами данных — SQL и NoSQL. Репозиторий носит образовательный характер и не предназначен для использования в продакшене.

Основная цель — на одном сквозном примере сравнить два подхода к хранению данных: реляционный (MySQL через ORM Sequelize) и документоориентированный (MongoDB).

## Текущее состояние

Миграция слоя данных с SQL на NoSQL завершена. Реляционная версия на Sequelize и MySQL осталась в истории git — её можно посмотреть в коммите `8ff6142` и сравнить с текущей.

| Аспект           | Состояние                                                                          |
| ---------------- | ---------------------------------------------------------------------------------- |
| Реализовано      | Каталог товаров, корзина, оформление заказа, административная часть (CRUD товаров) |
| Хранилище        | MongoDB, официальный драйвер `mongodb` — подключение в `util/database.js`          |

### Схема данных

Три коллекции вместо шести таблиц реляционной версии:

```js
// products
{ _id, title, price, imageUrl, description, userId }

// users — корзина встроена в документ пользователя
{ _id, name, email, cart: { items: [ { productId, quantity } ] } }

// orders — товары скопированы снимком
{ _id, user: { _id, name }, items: [ { product: { …копия товара… }, quantity } ] }
```

Заказ хранит копию товара, а не ссылку на него. Поэтому изменение цены или удаление товара из каталога не меняет уже оформленные заказы — в реляционной версии, где заказ ссылался на строку в `products`, это работало иначе.

## Технологии

| Категория        | Решение                         |
| ---------------- | ------------------------------- |
| Среда выполнения | Node.js                         |
| Веб-фреймворк    | Express 5                       |
| Шаблонизатор     | EJS 6                           |
| Работа с БД      | MongoDB, официальный драйвер    |
| Разбор запросов  | Встроенный `express.urlencoded` |
| Разработка       | nodemon 3                       |

## Структура проекта

```
app.js          Точка входа: конфигурация Express, middleware, ассоциации моделей
routes/         Определение маршрутов (shop.js — витрина, admin.js — управление товарами)
controllers/    Логика обработки запросов
models/         Модели предметной области (Product и User; корзина и заказы живут внутри User)
views/          Шаблоны EJS, разбитые по разделам и переиспользуемым фрагментам
public/         Статические ресурсы: стили и клиентские скрипты
util/           Инфраструктурные модули: подключение к БД, работа с путями
data/           JSON-файлы файлового хранилища с раннего этапа разработки
```

## Требования

- Node.js версии 20.6 или новее — используется встроенный флаг `--env-file`
- Доступный сервер MongoDB: кластер Atlas либо локальный экземпляр

## Установка и запуск

```bash
npm install
cp .env.example .env   # затем указать в .env свою строку подключения
npm start              # запуск через nodemon с автоперезагрузкой
npm run start-server   # запуск через node
```

Строка подключения читается из переменной `MONGODB_URI` и в исходный код не попадает; файл `.env` исключён из git. Приложение использует базу `shop`.

Локальный экземпляр для разработки поднимается одной командой:

```bash
docker run -d --name shop-mongo -p 27017:27017 mongo:7
```

В этом случае в `.env` достаточно строки `MONGODB_URI=mongodb://127.0.0.1:27017`.

Создавать схему заранее не нужно: MongoDB заводит коллекции при первой записи. При старте приложение создаёт единственного пользователя, если коллекция `users` пуста. Приложение доступно по адресу `http://localhost:3000`.

## Маршруты

**Витрина**

| Метод | Путь                   | Назначение                  |
| ----- | ---------------------- | --------------------------- |
| GET   | `/`                    | Главная страница            |
| GET   | `/products`            | Список товаров              |
| GET   | `/products/:productId` | Карточка товара             |
| GET   | `/cart`                | Содержимое корзины          |
| POST  | `/cart`                | Добавление товара в корзину |
| POST  | `/cart-delete-item`    | Удаление позиции из корзины |
| POST  | `/cart-update-item`    | Изменение количества позиции |
| GET   | `/checkout`            | Форма оформления заказа     |
| POST  | `/checkout`            | Создание заказа             |
| GET   | `/orders`              | История заказов             |

**Администрирование** (префикс `/admin`)

| Метод | Путь                       | Назначение                    |
| ----- | -------------------------- | ----------------------------- |
| GET   | `/add-product`             | Форма добавления товара       |
| POST  | `/add-product`             | Создание товара               |
| GET   | `/products`                | Список товаров для управления |
| GET   | `/edit-product/:productId` | Форма редактирования          |
| POST  | `/edit-product`            | Сохранение изменений          |
| POST  | `/delete-product`          | Удаление товара               |

## Ограничения

Учебный характер проекта допускает ряд упрощений, недопустимых в реальной разработке: параметры подключения к базе данных хранятся в исходном коде, аутентификация не реализована (пользователь определяется жёстко заданным идентификатором), валидация входных данных и обработка ошибок минимальны, автоматическими тестами (`npm test`) покрыт только валидатор данных заказа — остальной код тестами не покрыт.
