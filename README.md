# nosql-mongodb-project

Учебное веб-приложение (интернет-магазин) на Node.js и Express, созданное в рамках изучения серверной разработки и работы с базами данных — SQL и NoSQL. Репозиторий носит образовательный характер и не предназначен для использования в продакшене.

Основная цель — на одном сквозном примере сравнить два подхода к хранению данных: реляционный (MySQL через ORM Sequelize) и документоориентированный (MongoDB).

## Текущее состояние

Проект находится в процессе миграции слоя данных с SQL на NoSQL.

| Аспект           | Состояние                                                                                          |
| ---------------- | -------------------------------------------------------------------------------------------------- |
| Реализовано      | Каталог товаров, корзина, оформление заказа, административная часть (CRUD товаров)                 |
| Хранилище сейчас | MySQL, доступ через Sequelize — `util/database.js`, модели в `models/`                             |
| Следующий этап   | Перевод слоя доступа к данным на MongoDB; официальный драйвер `mongodb` уже добавлен в зависимости |

## Технологии

| Категория        | Решение                            |
| ---------------- | ---------------------------------- |
| Среда выполнения | Node.js                            |
| Веб-фреймворк    | Express 4                          |
| Шаблонизатор     | EJS                                |
| Работа с БД      | Sequelize (MySQL), драйвер MongoDB |
| Разбор запросов  | body-parser                        |
| Разработка       | nodemon                            |

## Структура проекта

```
app.js          Точка входа: конфигурация Express, middleware, ассоциации моделей
routes/         Определение маршрутов (shop.js — витрина, admin.js — управление товарами)
controllers/    Логика обработки запросов
models/         Модели предметной области (Product, User, Cart, Order и связующие сущности)
views/          Шаблоны EJS, разбитые по разделам и переиспользуемым фрагментам
public/         Статические ресурсы: стили и клиентские скрипты
util/           Инфраструктурные модули: подключение к БД, работа с путями
data/           JSON-файлы файлового хранилища с раннего этапа разработки
```

## Требования

- Node.js (проверялось на v24)
- Запущенный сервер MySQL с базой данных `node-complete`

Параметры подключения заданы в `util/database.js`. Перед первым запуском их следует привести в соответствие с локальным окружением.

## Установка и запуск

```bash
npm install
npm start              # запуск через nodemon с автоперезагрузкой
npm run start-server   # запуск через node
```

Схема базы данных создаётся автоматически при старте приложения (`sequelize.sync()`). Приложение доступно по адресу `http://localhost:3000`.

## Маршруты

**Витрина**

| Метод | Путь                   | Назначение                  |
| ----- | ---------------------- | --------------------------- |
| GET   | `/`                    | Главная страница            |
| GET   | `/products`            | Список товаров              |
| GET   | `/products/:productId` | Карточка товара             |
| GET   | `/cart`                | Содержимое корзины          |
| POST  | `/cart`                | Добавление товара в корзину |
| POST  | `/cart-delete-item`    | Удаление позиции из корзины |
| POST  | `/create-order`        | Оформление заказа           |
| GET   | `/orders`              | История заказов             |

**Администрирование** (префикс `/admin`)

| Метод | Путь                       | Назначение                    |
| ----- | -------------------------- | ----------------------------- |
| GET   | `/add-product`             | Форма добавления товара       |
| POST  | `/add-product`             | Создание товара               |
| GET   | `/products`                | Список товаров для управления |
| GET   | `/edit-product/:productId` | Форма редактирования          |
| POST  | `/edit-product`            | Сохранение изменений          |
| POST  | `/delete-product`          | Удаление товара               |

## Ограничения

Учебный характер проекта допускает ряд упрощений, недопустимых в реальной разработке: параметры подключения к базе данных хранятся в исходном коде, аутентификация не реализована (пользователь определяется жёстко заданным идентификатором), валидация входных данных и обработка ошибок минимальны, автоматические тесты отсутствуют.
